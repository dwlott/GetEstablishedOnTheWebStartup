# Quick Startup Greeting

Read `AGENTS.md`, [GettingStarted.md](GettingStarted.md), and
[WorkspaceAdoptionPrep.md](WorkspaceAdoptionPrep.md) first. Classify the root;
reset only identified template residue in an owner-confirmed adopted copy.
Preserve canonical repositories, established projects, owner data, and Git.

For a fresh startup, display this opening and all five questions once as a
preview. Then follow [QuickStartupWalkthrough.md](QuickStartupWalkthrough.md).
For a resumed interview, read its checkpoint and ask the next unanswered
question; do not repeat the opening or completed questions.

## Opening (display to owner)

```text
Welcome — let's make this workspace useful for your project.

Here are the five setup questions so you can see what's ahead. I'll ask them
one at a time and save your progress. You only need to answer; I'll handle
moving forward. One clear goal is enough, and you can skip a question or
continue later.
```

## Five setup questions (canonical preview)

```text
1. What business, project, or workspace setup are you trying to establish?
   (For example: organize a project, draft a book, start a service business,
   create a website, or maintain an existing website.)

2. What is the first outcome you want this workspace to produce?
   (One practical result is enough. Add more goals if you already have them.)

3. What should matter first in the next few sessions — repository organization,
   drafts, credibility, leads, reviews, or something else?

4. What devices and tools are you using for this work?
   (I will use what is already known and ask only about missing details.)

5. Do you have a prior folder, archive, notes, or repository to learn from?
   (If yes, describe it and roughly where it lives. I will record the path;
   copying or importing it requires your authorization.)
```

## During and after the questions

Use labels such as **Question 2 of 5 — desired outcome**. Ask the first
unanswered question, wait for the actual answer, acknowledge briefly, save it,
and lead into the next. An answer covering several questions settles all of
them. Do not require the owner to copy questions or type "next."

Capture goals and preferences as answers arrive; never invent owner facts.
If question 1 identifies an existing website, record that direction immediately
and use [ExistingWebsiteStartup.md](ExistingWebsiteStartup.md) for the short
maintenance follow-up. Do not substitute new-site or example-page work.

Finish the first-session order in [GettingStarted.md](GettingStarted.md), then
close with the practical outcome and one next action from
[PostQuickStartupRouting.md](PostQuickStartupRouting.md). Keep GitHub optional,
indexing opt-in, and references useful to the immediate task.
